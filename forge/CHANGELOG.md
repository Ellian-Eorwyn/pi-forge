# Changelog

## [Unreleased]

### Added

- Added an opt-in sources tree to the vault schema: declaring a **Sources root** section files every `type: source` note by its `source_kind` — `10 Sources/10.01 Book/Academic/Dissertation` — with the domain and subdomain labels as unnumbered subfolders that drift checking treats as detail, while the numbered kind folders are declared routes checked like any other. `project` never moves a source. Omitting the section leaves sources filing by domain exactly as before. `vault-organizer` gained `--reuse-frontmatter`, which files notes whose existing frontmatter already validates without a model call so a folder-only schema change does not re-derive a whole vault's classifications, and now pins a script-declared `type: source` and `source_kind` over the classifier's answer.
- Added a two-note transcript layout: processing writes the note made from the recording plus the recording under its own name as a `source_kind: transcript` source, linked from the note and back through `parent`, so a note reads at the length of what it says and the recording files with every other source. A new `split` mode moves the recording out of notes processed before this, deterministically and with every endpoint down, reconstructing byte-for-byte and backing up each note before rewriting it. Vaults whose schema cannot describe the second note keep the single combined note.

- Added a `vault-wiki` skill that installs the seven vault-owned wiki entry templates and expands thin entity notes into cited reference cards. Sources resolve through each canonical publisher's own API — Stanford Encyclopedia of Philosophy, Wikipedia, and per-topic equivalents — rather than through web search, so a citation names the work it came from. Only the sections a kind spec declares managed are rewritten: owner-authored `Notes`, frontmatter, and every unclaimed heading survive byte-for-byte, enforced by a post-merge comparison that fails the write rather than the check. Batch approval, per-id approval for anything the reviewer flagged, and a per-run revert.
- Added a `literature-library` skill that turns a citation list into a library: RIS/BibTeX parsing, bibliographic file naming, open-access acquisition with per-item deferral and `--retry-deferred`, and conversion of the acquired PDFs to Markdown under their bibliographic names, published through the hash-bound journal so a tampered file is caught by `validate`. Institutional access stays manual by design — the VPN it would need cannot be automated.
- Added a personal-context layer shared by `vault-capture`, `vault-transcripts`, `vault-organizer`, and `vault-connections`: a vault-owned register of cards compiled once and offered to each stage under `--profile` / `--no-profile`. Cards inform filing, drafting, and search wording; they are structurally forbidden from becoming note content, route-gated cards are refused wherever the destination is undecided, and an ambiguous or malformed register costs the layer rather than the run.
- Added reflection sections to generated memos alongside journals, with outside sources cited only when the material is already in hand — a link the person wrote, or a citation in a note the run imported. Nothing is fetched to support a reflection, and a connection citing anything else is dropped and reported rather than published.
- Added a schema marker for human-owned properties: a property the classifier is told nothing about, is stripped from the response if it answers anyway, and that the schema itself refuses unless it is declared optional. Lets a vault keep fields like `date` and `cover` that only a person can fill.
- Added optional Moshi hook coverage for this distribution. `moshi-hook` resolves its `pi` target from `PI_CODING_AGENT_DIR`, so install and `pi-forge-update` now point it at the pi-forge agent directory and let Moshi generate `agent/extensions/moshi-hooks.ts` itself — the daemon's own current hook rather than a vendored copy that goes stale on every Moshi release — falling back to a link against the standard `~/.pi` hook when generation cannot write there, restarting the daemon only when the hook actually changed so a no-op update cannot drop a live session's bridge, and leaving hosts without Moshi untouched and silent (`PI_FORGE_SKIP_MOSHI_HOOK` opts out).
- Added deterministic Gmail-style EML-to-Markdown conversion with preserved attachment manifests, plus document-ingest email batches that extract exact-quote evidence on the chat service, verify and synthesize on the thinking service, and publish a hash-bound cited digest.
- Added schema drift detection to `vault-organizer`: a severity-ranked comparison of the schema's compiled folder routes against the folders that actually exist, surfaced by `doctor`, warned about by every `organize` run, and blocking `--apply` unless `--allow-schema-drift` is passed. A new read-only `drift` mode audits the vault, and `drift --fix-schema <id>` corrects the schema side of findings the user names — backed up, surgically edited, and rolled back if the result does not re-parse clean. Structure below a declared route is never reported.
- Added a scoped vault voice-policy compiler and consistent `--voice` / `--no-voice` controls across `vault-capture`, `vault-transcripts`, and `vault-connections`. Owner journals receive vault-first reflection, external transcripts receive structured full-content cleanup, generated research introductions are labeled `Synthesis`, and resumable runs reject policy drift.
- Added a packaged restart-safe batch run contract and shared Python/JavaScript state helpers, with resumable document ingestion, file conversion, web collection/research, transcription chunks, transactional finalization, input refresh/retry controls, and context-bounded literature synthesis and deliverable queues.
- Added a refreshable `project-extraction` skill with source-backed evidence, reconciled control registers, a human-maintained status overlay, project-aware document routing, and PPTX OOXML ingestion.
- Added direct-first web research acquisition with stage artifacts, cache metadata, structured extraction, and explicit endpoint discovery.
- Added local-first deep web research scheduling with serialized model calls, cached SearXNG searches, embedding-ranked chunks, batched evidence extraction, and scheduler/ranking artifacts.
- Added settings-backed SearXNG and Playwright connected service defaults plus quick web search/read tools.
- Added the published `@ellian-eorwyn/pi-forge` package surface for no-clone installs and updates.
- Added opt-in cache-aware local inference scheduling with isolated interactive and project-extraction slots, activity leases, worker preemption, adaptive larger batches, focused views, extraction metrics, and source-backed Gantt outputs.
- Added hybrid search and resumable Inbox intake for live project-extraction repositories.
- Added a serial foreground project-extraction orchestrator, truthful coverage gates and labeled drafts, adaptive truncation recovery, model-assisted reconciliation, and Zoom JSON transcript provenance intake.
- Added a `vault-context` extension that recognizes an Obsidian vault at or above the working directory and injects its coordinates — root, schema note, note count, index state — once per session, so vault sessions start knowing which skill answers which question. Adds `/vault`; does nothing outside a vault.
- Added a `vault-connections` skill: hybrid semantic search over an Obsidian vault, per-id reviewed connection proposals merged additively into the `related` frontmatter property, and a wiki entity layer that turns unresolved wikilinks into schema-routed stub notes and backfills links to them. Extracted the shared schema compiler into `lib/vault_schema.py` so it and `vault-organizer` derive identical folder paths.
- Added reviewed `vault-connections import-run` publishing for validated literature, meta-literature, and deep-research runs, with schema-classified inbox reports, evidence-backed wiki notes, vault-owned templates, per-id approval, drift preflight, and atomic no-overwrite creation.
