# Changelog

## [Unreleased]

### Added

- Added `transcription export`, closing the seam between a finished recording and the vault. `vault-transcripts` consumes what a voice app drops into the vault inbox, and nothing turned this skill's `raw_segments.json` into that shape, so a recording transcribed here could not enter the vault pipeline at all without someone retyping it. The export writes italic `*MM:SS*` markers and the text, growing to `*H:MM:SS*` past an hour because that parser tells the two apart by counting colons and `62:05` would otherwise read as sixty-two minutes; `--inbox` names the file `YYYYMMDD HHMMSS-<id>.md`, the stamp `vault-transcripts` reads a date from, with the id taken from the source hash so re-exporting a recording overwrites its note instead of making a second one. There is deliberately no default speaker label: `capabilities.diarization` is false on every engine this service offers, so "Speaker 1" would be an assertion nobody measured, and `--speaker` is how a solo recording gets one. Without `--recorded-at` the date falls back to the source file's modification time, which is when this machine last touched a file rather than when the recording was made — a copied or re-exported recording carries the copy's date — so the result reports `date_source` and warns whenever it is a guess. Verified against the real parser rather than by eye: both shapes satisfy `is_transcript`, and both round-trip byte for byte, which is that skill's load-bearing invariant.
- Added transcription to `document-ingest`'s media path, which extracted `derived/audio.mp3`, wrote "Waiting for transcription", and left it there — nothing was waiting, and no caller ever transcribed it. It now delegates to the `transcription` skill rather than reimplementing a client, so the service, the correction dictionary and the run state have one owner, and it uploads the `audio.mp3` ffmpeg already produced for review because mp3 is a format the service decodes for itself. The document's heading is restored to the recording's own name, since the transcript is otherwise titled after the extracted track and every media document would be called `audio`. A transcription that cannot happen is never fatal: the placeholder returns naming the actual reason from `doctor`'s remediation, the audio stays on disk, and `record-transcript` remains the way to supply text by hand — one unreachable service should not fail a whole ingest batch.
- Added `skill-tuner`, which mines a completed pi session log for the friction that should become skill improvements — and produces a report bounded to a fixed token budget so another model can consume it whole. The division of labor is the service-split handoff's: a deterministic scan finds everything a script can find (the three error channels — `isError`, `stopReason: length`, and warnings buried in envelopes whose `isError` is false — plus compaction, stalls classified by boundary so a person being away overnight is not a pain point, byte-identical retry loops, re-pasted errors, and skill attribution from tool calls), and the chat model is handed those findings as seeds so its job is cause, attribution, and consequence rather than rediscovery — plus the categories no scan can see, ambiguity and knowledge reliance, which live in the thinking blocks. The session renders to a deterministic timeline in which every oversized payload is elided with head and tail kept — the example session's six largest lines held 61% of its bytes and one `forge_web_read` result was 419KB — so quotes are verified byte-exact against what the model actually saw and an elided middle is uncitable by construction; a quote that exists but cites the wrong entry relocates its locator deterministically instead of burning the corrective retry, because a small model fumbles line numbers far more often than it fabricates text. Extraction is serial so each chunk's open threads chain into the next — how a truncation loop spanning forty entries survives a chunk boundary — then one batched review on the thinking service with the evidence inline, escalation carrying the reviewer's objection, and an unreachable verifier recorded as **Not verified**, never as approval. The report allocates its budget deterministically (fixed sections and the appendix reserved first, authored sections proportional to severity-weighted evidence mass), every claim must cite an appendix-resolvable `[p######]` id, an overrun re-authors the fattest section smaller, and nothing is ever silently truncated. A section's character budget is clamped to what one call can actually emit — the first live run handed a section 30,086 characters against a 4,096-token cap, which buys a truncated response, a failed gate, and a wasted retry — so authoring reserves 8,192 output tokens like extraction and the allocator is structurally incapable of asking for more than that; measured on the example session, four of five sections genuinely needed more than 4,096. There is deliberately no `refresh`: a session log is immutable, so drift means a different file and a new run. Evidence rows carry `sessionId` so a future suite can aggregate runs across sessions without re-mining.
- Added grounding for the recommendations, because a verified diagnosis paired with an invented fix is worse than no fix: an agent acting on it edits paths that do not exist. Verification reviews evidence — claim against quote against deterministic seed — and nothing reviewed whether a proposed fix was real, so the first live report proposed writing notes to `$VAULT/wiki/<subdomain>/` for a vault whose notes live in `09 Wiki/9.01 Concepts`, reading a schema from `$VAULT/schema/wiki/index.md` when the schema is one note at `99 Meta/99.02 Schemas/0.00 Vault Schema.md`, and tuning a `max_context_wait` that exists nowhere in the distribution — a small model reaching for a tidier convention than the real one. Every path, flag, and identifier a recommendation names is now checked against what the session actually demonstrated, drawn from the raw log rather than the elided timeline so a path that only appeared inside an elided payload is not punished. A path grounds when all of its literal segments of four or more characters appear as real path segments and at least one is six or more, which is what stops a bare `wiki` inside `09 Wiki` from grounding a whole fabricated tree; numbered vault names are indexed with and without their prefix, so naming `Personal Context.md` rather than `0.03 Personal Context.md` is describing a real file rather than inventing one. Ungrounded paths and flags cost one rewrite request naming them; grounding is deliberately not a hard gate, because a section whose diagnosis is verified and whose fix names one invented path is still worth keeping, so whatever survives is listed under **Unverified Recommendation Details** instead of discarding the section. The report's own controlled vocabulary is exempt — flagging `deterministic_guard` in every section buried the six genuinely invented identifiers the check exists to surface. `--ground-root` lets paths that exist in a repo or vault count alongside what the session shows. On the example session the pass fired twice, both rewrites succeeded, and the fabricated paths are gone.

- Added `vault-curator`, which researches how a field actually catalogues its records and proposes what that means for the vault's schema. The existing route for this was the classifier's `suggestions` array — free-text strings that land in a report — and the reason it stayed that thin is that the model doing the proposing is the local non-thinking one, whose measured failure is breadth rather than accuracy: `docs/service-split-handoff.md` §2.1 found it covering four categories where a reasoning model covered eight. Asked how to catalogue anything it reaches for identification, description and classification, and never asks who governs the names, where a specimen came from, what scale a condition is graded on, or whether a dated record is a different kind of note from a reference card — which is where every real schema decision lives. So the enumeration of what a catalogue must decide is shipped in `references/catalog-dimensions.json` and a dimension the model omits is restored as applicable rather than read as absent; the field's practice is fetched through `web-research deep` and a practice citing no claim is dropped, so a run with no network proposes nothing and says so; reconciliation picks from eleven named moves with `approved-property` deliberately absent, because the vault's property list is global and closed and a nested value is stripped on the next filing pass; and every row is applied to a candidate copy of the schema note which is reparsed, revalidated for colliding paths, and re-drift-checked against the real vault before anyone reads it. Numbers come from `free_numbers`, never from a model. The schema's own "begin as a topic hub" rule is encoded rather than left to taste: a route with too few notes is demoted unless the field's records accumulate, which is the clause that keeps it from refusing a `nature` domain that was correct and empty. Applying is per-id and additive only — no edit, no removal, no renumber, and nothing at all in **Approved properties** or the **Project registry** — and `apply` re-proves against the note as it is at that moment, because a row proved against a note the owner has since edited is not proved.
- Added additive insertion to `forge/lib/vault_schema.py`: `insert_schema_row`, `insert_registry_bullet`, `insert_subdomain_section`, `candidate_schema_text`, and `free_numbers`. Until now the only code that wrote the schema note changed a single `Number` cell, and everything else about the note was safe because nothing could reach it. These widen that opening by exactly one operation and are written to the same surgical contract: backtick style is taken from the column's existing cells and spacing from the last row, so an inserted row is indistinguishable from a hand-written one, and a value the table already carries is refused. `free_numbers` excludes the numbers domain-level projects already hold when asked for a subdomain slot, because `<domain>.<nn>` is one namespace shared by both — a collision `validate_derived_paths` would have caught, but that should never have been proposed.
- Added a note-format standard, so the body of a note has the same visual grammar everywhere and one place declares it. The vault's snippets styled generated apparatus and dashboards but nothing in between, so an ordinary note was a title and a run of identical `##` headings with nothing to navigate by. A new vault note, `99 Meta/99.02 Schemas/0.04 Note Format.md`, declares the block order and a nine-callout registry in which colour carries epistemic status — `summary` cyan, `key` blue, `define` yellow, `evidence` green, `reflection` purple, `question` pink, `caution` orange — while `connections` and `provenance` take a quiet register, because apparatus is not a claim. Red stays unclaimed so Obsidian's `danger` and `failure` still mean danger and failure. `question` moves off the orange it shares with `warning` in stock Obsidian, which rendered "unresolved" and "dangerous" identically. `99 Meta/99.03 Templates/0.00 Template Blueprint.md` is the same rules as a file to copy, and the folder held only wiki cards before it. `forge/lib/vault_format.py` parses the registry and proves the note, the stylesheet, `vault_reflection.py`, and the templates still agree — a callout added to one and forgotten in the rest renders as stock blue with a pencil icon, which reads as a decision rather than a mistake. Nothing is injected into a drafting prompt: the generators already emit only registered callouts, and the registry is a contract rather than more prompt budget.
- Added `vault-compose`, the first note-writing path that is not a closed pipeline over one kind of input. It takes a typed source set — research claims, existing vault notes, excerpts of a conversation — and assembles a note from the blocks `0.04 Note Format.md` declares, so three shapes reduce to one run spec differing only in the `kind` of their sources and nothing downstream knows which one it is. Unlike `vault-capture` it **proposes**: capture's words are the user's and only the split is the machine's, so writing straight to the inbox is fair, but here the model chose the content and the first read of a note should come before it lands. Outline and draft are separate calls for the same reason capture splits its own — a call that decides structure and a call that writes prose have different failure modes, and mixing them means a bad structural choice arrives wearing finished sentences. Blocks come back as plain lines and the renderer adds every callout, so no deterministic check depends on a model getting `>` prefixes right. Grounding is per block against the sources *that block cited*, which is what stops a note whose sections are each individually plausible from being collectively a collage — deliberately the opposite of what `daily` does, and both are right: a day of memos is cleaned as one document before the model sees a section boundary, while here each source is held and quoted separately, so the citation is a real claim about provenance and can be enforced as one. No `domain` is written: guessing one buries a note where nothing looks for it, so the missing required property is reported as a warning rather than held, since holding for it would hold every note the skill ever makes. A first live run over three real notes showed the layering earning its keep — the deterministic gates passed, and the thinking reviewer caught a fabricated parameter count and an invented quantization scheme, the kind of plausible claim whose individual words are all present in the sources.
- Added `forge/lib/vault_research.py` and the `research` intent. The joins from a deep-research run — claim to evidence, evidence to quote, quote to URL — were private to `vault-connections`, and both note-making paths need them, so they moved to a lib: they encode facts about the *run format* rather than about notes, and a change to what `web-research` writes should break one file. A research spec names the run directory instead of transcribing it, because the claims and the quotes under them are already on disk and a spec that restated them could restate them wrong. Each surviving claim becomes one source unit whose text is the claim followed by its quotes, carrying the URL those quotes came from — that pairing is what makes grounding meaningful here, since a research note may use a claim's wording and the wording of the evidence beneath it and nothing else. A claim the research run's own reviewer flagged is dropped, and so is one whose every quote was flagged: a claim with nothing behind it is exactly what a research note should not repeat.
- Added a plural rule to the grounding check. A source saying "PC" and a note saying "PCs" was reported as an invented name: the stem rule that roots "ordering" in "order" starts at four characters, and "pcs" is three. Pluralizing a term the source used is writing, not invention.
- Added `forge/lib/vault_compose.py`: a source set, a grounding check over it, and one note renderer. Every note-writing path in forge is a closed pipeline that hardcodes its own section set, frontmatter keys and destination, so none of them can produce the note `0.04 Note Format.md` describes; `render_note` assembles a note in whatever order that note declares, refusing a block the grammar does not name and any block whose `Written by` is `owner`. The load-bearing part is the source set. `vault-capture.invented_specifics` holds a note for any capitalized token or URL with no root in *the braindump*, which is exactly right with one braindump and is also why a research note, a note synthesized from other notes, and a note made from a conversation cannot be written at all — their content legitimately comes from elsewhere, so every sentence reads as invention. `ungrounded_specifics` replaces "rooted in the braindump" with "rooted in the units this block claims to rest on", keeping the property and widening the world; `cited_ids` narrows the corpus per block, so a section may not quietly borrow a name from a source it never cited, which is what stops a note whose sections are each plausible from being collectively a collage. Wikilinks join names, URLs and figures as a checkable specific — capture could never check those, because a braindump names no vault notes. `dropped_units` is new and exists because `coverage_ratio` measures a corpus as a whole and is blind to one member of it being ignored entirely, which is the failure fan-in actually produces: six recordings merged into a day can score well overall while the quietest contributed nothing, and a log that silently omits a recording is worse than no log because nothing about it looks wrong. The primitives moved out of `vault-capture` rather than being copied, `invented_specifics` stays as a wrapper so its callers and tests did not move, and all 92 of that skill's tests pass unchanged. `content_words` now folds diacritics, which `vault-transcripts` learned and capture never got: a source saying "Jose" and a note writing "José" is a correction, not an invention. `check_grammar` reads a note with fenced blocks and inline code spans blanked out — a note that documents syntax is full of it, and checked raw the vault's own format note reports two level-one headings and inline HTML in the note that forbids both.
- Fixed the guard that stops a draft from imitating machine-written prose. `vault-capture` excluded a note from its exemplars when `capture_type: generated` or `processed_by` was set. Neither fires for `vault-transcripts` output: that skill correctly writes `capture_type: voice`, because the property records the *channel* a note arrived by, and `processed_by` is not an approved property in every vault — where it is not, `serialize_frontmatter` drops it, and zero notes carry it. In the vault this was built against that is every transcript-derived note, so the guard against a model learning its own habits had been open for as long as transcripts have been processed. The marker is now the `> [!provenance]-` block, which `0.04 Note Format.md` already requires to be accurate about what made a note and which a hand-written note does not get: it survives filing, and no schema can drop it. A note the owner typed up from a recording still reads as theirs.
- Added the `daily` mode that drives it, with its own run-state phases (`scan → dedupe → classify → group → assemble → plan`), `--daily-min-recordings`, and `--scan filed` for exports already moved into the sources tree by hand. Cleanup runs on the merged day through the existing chunking and fidelity gates; one further chat call returns a title, a summary paragraph, and topical sections with the recordings each drew on. Run against the six real recordings it was designed from, it produces one journal note plus six source notes — seven files where the old path made twelve — all left in `00 Inbox`, because routing them means choosing a domain and the only way to choose one there is to hardcode it, which an earlier version did as `personal` and got wrong for a workday about a dissertation. Three things the live runs changed: the recordings are named from their own per-recording classification rather than from the day's title, which was producing six files called the same thing — the state merging exists to end; grounding reads the whole day rather than each section's citations, because a day is merged and cleaned as one document *before* the model sees any section boundary, so narrowing by its attributions flagged Herder, Mochi, Claude, ITO, Mac Whisper and Linux as invented when every one was spoken that morning in a different recording than the section carrying it; and a recording id the day does not have is dropped rather than refused, after a six-recording day drew `s-0007` through `s-0011` — the ids feed the time markers and nothing else, so an invented one costs nothing to discard, while a section left citing nothing real still holds the day. Grounding also reads only what the model wrote: checking the rendered note means checking the pipeline's own output against the sources, which reports the note's title as an invented name every time it is not a phrase somebody said out loud.
- Added the deterministic core of a daily voice log to `vault-transcripts`: `group_daily`, `merge_transcripts`, `render_merged_transcript`, `daily_marker`, `daily_title`, `daily_source_lines`, `daily_metadata`, `daily_provenance`, `build_daily_note` and `check_daily_note`. Short memos recorded through a day are fragments alone — one real recording is 61 words and ends "I don't remember what it is" — and the pipeline could only ever make one note per file, so a day of thinking became a dozen notes that mean nothing separately. Grouping is same-day, same recording type, owner-authored, two or more, and deliberately *not* content similarity: the hand-built log this reproduces spans a coding tool, a to-do list, groceries and two feature ideas, so a similarity threshold would have split exactly the group a person sat down and made on purpose. `conversation`, `meeting`, `therapy` and `lecture` never group, because each is a document in its own right. Merging rebases every recording's `*MM:SS*` offsets onto its filename's start stamp, since concatenating them raw produces a day that restarts at zero once per recording; that one monotone clock is also what lets a section's `(~HH:MM)` marker be computed rather than guessed, and the markers reproduce the hand-built log's exactly, including the en-dash range `(~10:39–10:41)` spanning two recordings and the collapse to `(~10:38)` when two fall in one minute. `parse_filename` now keeps the seconds it always parsed and discarded, so two memos begun in the same minute stay in the order they were spoken. `--tiny-words` will be measured on the merged transcript rather than per recording, which is the point: a 61-word fragment gets no summary alone and a real one as part of a ~1,400-word day. Frontmatter is `capture_type: voice` with the machine's hand recorded in the provenance block, matching the note this reproduces. The composing call supplies a title, a summary paragraph, and which recordings each section drew on; everything that has to be exact — heading, markers, recording list, provenance — is written in code.
- Added a block-grammar compiler to `forge/lib/vault_format.py`, reversing that last sentence. "The registry is a contract rather than more prompt budget" held exactly as long as no model chose which blocks a note gets: every generator emitted a fixed section set, so it could be checked against the registry without ever being told about it. A composer chooses, so the grammar has to reach the drafting call too. `parse_block_grammar`, `parse_type_shapes`, `parse_format`, `compiled_format_for`, `prompt_prefix`, `block_index`, `writable_blocks` and `format_state` make the module a real sibling of `vault_voice` and `vault_profile`, which have always compiled theirs. The registry half is untouched and still only ever checked, never prompted. `## Per-type shapes` already parsed as shipped and needed no vault edit; the block order did, because a fenced code block is not a table and deriving one from it means guessing at exactly the moment the module's own docstring warns against guessing — and because `Written by` cannot be derived from the fence at all, which is the column that lets a renderer refuse `## Notes` from the grammar rather than from a hardcoded constant. The new `### Block order` table is checked against the fence above it, the same move the registry already makes against the stylesheet. Reading the fence deliberately does not use `section_bounds`: the fence's own content includes `# Title`, `## Sources` and `## Notes`, so a heading-aware scan ends the section three lines in, inside the block it was trying to read. A vault that has not adopted the table compiles to no blocks and an empty prefix rather than an error, because absence and malformation are different findings and every vault started in the first state. The prefix budget is 2400 rather than the voice note's 1800: groups are appended in order, and at 1200 the whole prefix went to the block list and stated no prohibition at all. Prohibitions are also read with wrapped continuation lines folded back in — this note's rules are hard-wrapped, and read line-wise the first one stops at "The CSS", which is worse than no rule.
- Added `vault_format.load_and_check` to `vault-organizer doctor`, giving it its first production caller. It has been able to prove the note, the stylesheet, `vault_reflection.py` and the templates still agree since it was written, and nothing ever asked it to, so the check could only be run by hand by someone who already suspected a problem. A vault with no format note, or a format note but no stylesheet, reports `configured: false` and stays passing — that is a vault that has not adopted the registry, not a broken one. Only a vault that declares a registry and then contradicts it fails.
- Added the note-format note to the injected vault context. The session block named `0.00 Vault Schema.md` and nothing else, so a model in a vault session was told how a note is *filed* and never that a note is *arranged* — it could write something that passed every check and still did not look like the vault's own notes. Absent, it costs no line.
- Added a readability fix for every callout in the vault. Obsidian paints a callout title at its raw accent colour, which for yellow on a light background is 1.79:1 — well under WCAG AA, and this vault runs light. The icon and border keep the full accent, since that is what identifies a block at a glance, and the title text is mixed toward body text until it clears 4.5:1. Measured across all nine callouts in both light and dark, 45% accent is the largest share that clears AA everywhere; the worst case is 4.76:1, against 1.79:1 before. Applied as a `--callout-title-color` override, so it survives Obsidian reorganising its own callout markup, and it reaches stock callouts too.
- Added a vault-wide heading treatment. Callouts only reach notes that get rewritten, and headings are the structure the other six thousand notes already have. CSS cannot read a heading's text — Obsidian sets `data-heading` only in Publish — so per-section colour keyed to a heading name is not achievable without a plugin, and the treatment is a uniform left rule instead: it marks where a section starts without claiming to know what kind it is. Applied in reading view and live preview both, excluded from callout interiors and from dashboards, where `loom-dashboard.css` turns `h2` into an uppercase eyebrow.

- Added a declared vault, so a session outside one knows where it is. The `vault-context` extension finds a vault by walking up from the working directory for `.obsidian/`, which means a session started in a code checkout or a downloads folder has never had any way to know a vault exists — "put this in my vault" could only be answered by asking. A `forgeVault` path in the agent's `settings.json` now renders the vault root and its inbox into the installed profile on every install and update, which is what makes it survive one, and the vault detected by the extension still wins wherever both apply. Obsidian's own vault registry is deliberately not consulted: it lists every vault ever opened, marks more than one of them open, and orders them by last use, so on a machine with a scratch vault beside a real one every available signal points at the wrong vault. Files brought in from outside now land in `00 Inbox` and stop there, for `vault-organizer` to classify later on demand or on a schedule; since only Markdown is filed from the inbox, other formats are converted first or the agent says plainly that the file will sit there untouched. An install that declares no `forgeVault` behaves exactly as it did before.

- Added optional Obsidian CLI support to the vault skills — an accelerator and a verifier, never a dependency. Every skill still works on any folder of Markdown with no Obsidian installed, and does exactly what it did before; when Obsidian 1.12.7+ happens to be running, `forge/lib/obsidian_cli.py` asks it the questions pi-forge would otherwise have to approximate. Renames and moves go through it so inbound links follow the note, in frontmatter as well as prose — the gap `vault-organizer` has documented since it was written, and the one `vault-transcripts` opens every time it renames a recording from its timestamp to its title. `drift` gained a property-vocabulary check that compares the schema's approved properties against what the vault actually holds; on a real 2,501-note vault it found 19 undeclared properties in 30ms, which no amount of folder-route checking could have surfaced. `doctor` reports whether the CLI is usable and compares our frontmatter parser against Obsidian's on a sample of notes, so a disagreement becomes a bug to fix in the pure-Python path rather than a difference nobody sees. `propose` lists the notes nothing links to, which needs a reverse link index this skill has never had; `wiki` cross-checks its unresolved-link set against Obsidian's and stops proposing a stub for a target an existing note already answers to by alias. Base files are evaluated rather than string-matched, and are never rewritten. The CLI exits 0 whether it succeeded or failed, so nothing here trusts a return code; writes are two commands that will not grow, each one backed up, hash-verified, journalled, and restored if the app touches a line that never had a link on it. `--link-rewrite {auto,off,require}` chooses the policy, and `FORGE_OBSIDIAN_CLI=off` turns the whole thing off. See `docs/obsidian-cli.md`. The note index gained an `aliases` field, so `vault-connections` rebuilds it once on the next run; embeddings are keyed separately by body hash and are not recomputed.
- Added a keyed provider tier and a daily budget ledger. Six search providers upgrade the registry when a free key is present — the Guardian and the New York Times for news, Wolfram|Alpha for computation, and Marginalia, Exa and Tavily as general indexes that are not scrapers of somebody else's engines — and each is skipped with a logged reason when no key is configured, so a machine nobody has set up behaves exactly as it did before. Four academic providers join the existing nine: OpenAlex, CORE, DBLP, and OpenCitations, which like Unpaywall takes the DOIs the search providers found rather than a query. Semantic Scholar and PubMed have declared an optional key since they were written and never read one; now they do. Most services publish a request rate, which spacing already handled, but OpenAlex and the NYT publish a daily allowance instead, so a ledger at `~/.pi-forge/cache/web-research/budget.json` skips an exhausted provider rather than retrying into a refusal. OpenAlex reports its own remaining balance on every response, and the ledger records what the service said rather than a local guess.
- Added `reference-resolve`, which asks one source which of its entries could be about a subject and answers with unranked candidates on stdout — no run directory, because a lookup is not a run — plus the `forge_reference_lookup` tool. Deciding which candidate is *about* a subject stays with the caller: a source's own relevance order is not that judgement.
- Added a routed search provider registry, so a question goes to a source that can answer it instead of always going through one metasearch scraper. Seventeen direct providers ship with no credentials at all — Wikipedia, Wiktionary and Wikidata; the Stanford Encyclopedia of Philosophy matched against its own published index, InPhO and the IEP; SuttaCentral, CBETA and BDRC; Open Library, Project Gutenberg, Internet Archive, the Library of Congress and HathiTrust; GDELT for news; Stack Exchange and Hacker News — and the query's identifiers and topic decide which are asked. An identifier is looked up rather than searched, because no document contains both the citation "MN 118" and the word it was asked alongside. SearXNG becomes the last provider tried rather than the only one, so a disabled or throttled instance now costs open-ended web results instead of the whole search. An optional `connectedServices.apiKeys` block upgrades providers that offer a free key; a provider without one is skipped with a logged reason, never an error.
- Added `forge/lib/http-fetch.mjs`, the shared outbound transport: retry with backoff honouring `Retry-After`, per-host request spacing, a circuit breaker, one SSRF guard in place of three divergent copies, and redaction of credential-bearing query parameters before any URL is archived. Before it, no HTTP call in the distribution retried — `withRetry` covered LLM calls only — and a timed-out fetch was recorded as a permanent failure because the message said "timed out" while the matcher looked for "timeout".

### Changed

- Rebuilt `vault-transcripts`'s `process` (and `reprocess`) around two model calls per note instead of six to nine stages. One **writer** call on the bulk tier reads the whole recording and returns the classification, the cleaned body, and the summary together — the 12,000-character chunk budget was sized for a context window four generations gone, so chunking now begins at 100,000 characters and almost every real note is one call. One **review** call on the thinking tier then reads the whole raw transcript beside the whole assembled note and signs off, **fixes the note in place**, or holds it with a reason code from a fixed taxonomy (`source_defect`, `structural_after_fix`, `writer_invalid`, …). That fixing-directly is the change of kind: the meaning-judge this replaces could only hold, hand the objection to a repair loop on another service, and re-verify — six stages (batched note-verify, utterance spot-check, whole-note judge, chat repair, think re-verify, xhigh escalation redo) that the 2026-08-19 inbox session spent ~4.5 hours failing through for 13 notes, with 9 full re-cleans burned on a solo-label gate whose fix was a rename. The deterministic word-overlap floors (length ratio, rare-word retention, utterance locator, invented-words ceiling) became advisory measurements that travel to the reviewer as named suspicions and re-arm as holds only when no reviewer runs; the structural contract — one `# Transcript` heading, the raw section byte-identical to the recording, the summary's shape — still gates absolutely, including on the reviewer's own fixes, which get one corrective re-ask at deep reasoning before holding. Timestamp lines and stray level-one headings in a cleaned body are normalized silently instead of costing a model turn. `forge_verify.repair_until_verified` is gone with its only caller.

### Changed

- Changed `vault-capture` to render a note's reflection as collapsed callouts — `[!reflection]` per section, `[!connections]` for connections — matching what `vault-transcripts` writes, so generated material reads as generated in both kinds of note. Drafting still writes `##` headings and the deterministic checks still read them; the rewrap happens afterwards, on the way into the file, and takes only the trailing run of sections belonging to the note's kind, in that kind's order — a note that writes its own `## Next steps` mid-body keeps it. `render_callout` moves to `lib/vault_reflection.py`, beside the section vocabulary the two skills already share.
- Changed the `vault-transcripts` cleanup register from a light fidelity edit to spoken-to-written: filler and verbal scaffolding, false starts, repeated phrases, and circumlocutions whose meaning is unambiguous are removed, in the speaker's own words and voice, so a transcript reads as prose rather than as speech. Therapy recordings keep the older, stricter contract — nothing condensed, weighted hesitation preserved. The cleaned/source ratio floor moves from `0.5` to `0.4` and thirteen discourse adverbs join the stopword list, because a register that legitimately compresses would otherwise be held for review as though it had summarized. `PROMPT_VERSION` moves to `v5`, so run directories from before the change refuse to resume rather than mixing two registers.
- Changed the transcript note layout: everything the pipeline generates is now a callout and sits above the speaker's words — the summary open, each reflection and connections section collapsed — where reflections were previously bare `##` headings below the cleaned text and indistinguishable from headings the cleanup itself wrote. The generated apparatus is stripped out of the passage the fidelity reviewer sees, so a summary can no longer answer for a cleanup that dropped an utterance.
- Changed the seven `vault-wiki` templates to render the opening definition as an `[!abstract]` callout. Wrapping is idempotent, and notes that already exist keep their plain-prose leads until their next expansion.
