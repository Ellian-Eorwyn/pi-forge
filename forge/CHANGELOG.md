# Changelog

## [Unreleased]

### Added

- Added `skill-tuner`, which mines a completed pi session log for the friction that should become skill improvements — and produces a report bounded to a fixed token budget so another model can consume it whole. The division of labor is the service-split handoff's: a deterministic scan finds everything a script can find (the three error channels — `isError`, `stopReason: length`, and warnings buried in envelopes whose `isError` is false — plus compaction, stalls classified by boundary so a person being away overnight is not a pain point, byte-identical retry loops, re-pasted errors, and skill attribution from tool calls), and the chat model is handed those findings as seeds so its job is cause, attribution, and consequence rather than rediscovery — plus the categories no scan can see, ambiguity and knowledge reliance, which live in the thinking blocks. The session renders to a deterministic timeline in which every oversized payload is elided with head and tail kept — the example session's six largest lines held 61% of its bytes and one `forge_web_read` result was 419KB — so quotes are verified byte-exact against what the model actually saw and an elided middle is uncitable by construction; a quote that exists but cites the wrong entry relocates its locator deterministically instead of burning the corrective retry, because a small model fumbles line numbers far more often than it fabricates text. Extraction is serial so each chunk's open threads chain into the next — how a truncation loop spanning forty entries survives a chunk boundary — then one batched review on the thinking service with the evidence inline, escalation carrying the reviewer's objection, and an unreachable verifier recorded as **Not verified**, never as approval. The report allocates its budget deterministically (fixed sections and the appendix reserved first, authored sections proportional to severity-weighted evidence mass), every claim must cite an appendix-resolvable `[p######]` id, an overrun re-authors the fattest section smaller, and nothing is ever silently truncated. A section's character budget is clamped to what one call can actually emit — the first live run handed a section 30,086 characters against a 4,096-token cap, which buys a truncated response, a failed gate, and a wasted retry — so authoring reserves 8,192 output tokens like extraction and the allocator is structurally incapable of asking for more than that; measured on the example session, four of five sections genuinely needed more than 4,096. There is deliberately no `refresh`: a session log is immutable, so drift means a different file and a new run. Evidence rows carry `sessionId` so a future suite can aggregate runs across sessions without re-mining.

- Added `vault-curator`, which researches how a field actually catalogues its records and proposes what that means for the vault's schema. The existing route for this was the classifier's `suggestions` array — free-text strings that land in a report — and the reason it stayed that thin is that the model doing the proposing is the local non-thinking one, whose measured failure is breadth rather than accuracy: `docs/service-split-handoff.md` §2.1 found it covering four categories where a reasoning model covered eight. Asked how to catalogue anything it reaches for identification, description and classification, and never asks who governs the names, where a specimen came from, what scale a condition is graded on, or whether a dated record is a different kind of note from a reference card — which is where every real schema decision lives. So the enumeration of what a catalogue must decide is shipped in `references/catalog-dimensions.json` and a dimension the model omits is restored as applicable rather than read as absent; the field's practice is fetched through `web-research deep` and a practice citing no claim is dropped, so a run with no network proposes nothing and says so; reconciliation picks from eleven named moves with `approved-property` deliberately absent, because the vault's property list is global and closed and a nested value is stripped on the next filing pass; and every row is applied to a candidate copy of the schema note which is reparsed, revalidated for colliding paths, and re-drift-checked against the real vault before anyone reads it. Numbers come from `free_numbers`, never from a model. The schema's own "begin as a topic hub" rule is encoded rather than left to taste: a route with too few notes is demoted unless the field's records accumulate, which is the clause that keeps it from refusing a `nature` domain that was correct and empty. Applying is per-id and additive only — no edit, no removal, no renumber, and nothing at all in **Approved properties** or the **Project registry** — and `apply` re-proves against the note as it is at that moment, because a row proved against a note the owner has since edited is not proved.
- Added additive insertion to `forge/lib/vault_schema.py`: `insert_schema_row`, `insert_registry_bullet`, `insert_subdomain_section`, `candidate_schema_text`, and `free_numbers`. Until now the only code that wrote the schema note changed a single `Number` cell, and everything else about the note was safe because nothing could reach it. These widen that opening by exactly one operation and are written to the same surgical contract: backtick style is taken from the column's existing cells and spacing from the last row, so an inserted row is indistinguishable from a hand-written one, and a value the table already carries is refused. `free_numbers` excludes the numbers domain-level projects already hold when asked for a subdomain slot, because `<domain>.<nn>` is one namespace shared by both — a collision `validate_derived_paths` would have caught, but that should never have been proposed.
- Added a note-format standard, so the body of a note has the same visual grammar everywhere and one place declares it. The vault's snippets styled generated apparatus and dashboards but nothing in between, so an ordinary note was a title and a run of identical `##` headings with nothing to navigate by. A new vault note, `99 Meta/99.02 Schemas/0.04 Note Format.md`, declares the block order and a nine-callout registry in which colour carries epistemic status — `summary` cyan, `key` blue, `define` yellow, `evidence` green, `reflection` purple, `question` pink, `caution` orange — while `connections` and `provenance` take a quiet register, because apparatus is not a claim. Red stays unclaimed so Obsidian's `danger` and `failure` still mean danger and failure. `question` moves off the orange it shares with `warning` in stock Obsidian, which rendered "unresolved" and "dangerous" identically. `99 Meta/99.03 Templates/0.00 Template Blueprint.md` is the same rules as a file to copy, and the folder held only wiki cards before it. `forge/lib/vault_format.py` parses the registry and proves the note, the stylesheet, `vault_reflection.py`, and the templates still agree — a callout added to one and forgotten in the rest renders as stock blue with a pencil icon, which reads as a decision rather than a mistake. Nothing is injected into a drafting prompt: the generators already emit only registered callouts, and the registry is a contract rather than more prompt budget.
- Added a readability fix for every callout in the vault. Obsidian paints a callout title at its raw accent colour, which for yellow on a light background is 1.79:1 — well under WCAG AA, and this vault runs light. The icon and border keep the full accent, since that is what identifies a block at a glance, and the title text is mixed toward body text until it clears 4.5:1. Measured across all nine callouts in both light and dark, 45% accent is the largest share that clears AA everywhere; the worst case is 4.76:1, against 1.79:1 before. Applied as a `--callout-title-color` override, so it survives Obsidian reorganising its own callout markup, and it reaches stock callouts too.
- Added a vault-wide heading treatment. Callouts only reach notes that get rewritten, and headings are the structure the other six thousand notes already have. CSS cannot read a heading's text — Obsidian sets `data-heading` only in Publish — so per-section colour keyed to a heading name is not achievable without a plugin, and the treatment is a uniform left rule instead: it marks where a section starts without claiming to know what kind it is. Applied in reading view and live preview both, excluded from callout interiors and from dashboards, where `loom-dashboard.css` turns `h2` into an uppercase eyebrow.

- Added a declared vault, so a session outside one knows where it is. The `vault-context` extension finds a vault by walking up from the working directory for `.obsidian/`, which means a session started in a code checkout or a downloads folder has never had any way to know a vault exists — "put this in my vault" could only be answered by asking. A `forgeVault` path in the agent's `settings.json` now renders the vault root and its inbox into the installed profile on every install and update, which is what makes it survive one, and the vault detected by the extension still wins wherever both apply. Obsidian's own vault registry is deliberately not consulted: it lists every vault ever opened, marks more than one of them open, and orders them by last use, so on a machine with a scratch vault beside a real one every available signal points at the wrong vault. Files brought in from outside now land in `00 Inbox` and stop there, for `vault-organizer` to classify later on demand or on a schedule; since only Markdown is filed from the inbox, other formats are converted first or the agent says plainly that the file will sit there untouched. An install that declares no `forgeVault` behaves exactly as it did before.

- Added optional Obsidian CLI support to the vault skills — an accelerator and a verifier, never a dependency. Every skill still works on any folder of Markdown with no Obsidian installed, and does exactly what it did before; when Obsidian 1.12.7+ happens to be running, `forge/lib/obsidian_cli.py` asks it the questions pi-forge would otherwise have to approximate. Renames and moves go through it so inbound links follow the note, in frontmatter as well as prose — the gap `vault-organizer` has documented since it was written, and the one `vault-transcripts` opens every time it renames a recording from its timestamp to its title. `drift` gained a property-vocabulary check that compares the schema's approved properties against what the vault actually holds; on a real 2,501-note vault it found 19 undeclared properties in 30ms, which no amount of folder-route checking could have surfaced. `doctor` reports whether the CLI is usable and compares our frontmatter parser against Obsidian's on a sample of notes, so a disagreement becomes a bug to fix in the pure-Python path rather than a difference nobody sees. `propose` lists the notes nothing links to, which needs a reverse link index this skill has never had; `wiki` cross-checks its unresolved-link set against Obsidian's and stops proposing a stub for a target an existing note already answers to by alias. Base files are evaluated rather than string-matched, and are never rewritten. The CLI exits 0 whether it succeeded or failed, so nothing here trusts a return code; writes are two commands that will not grow, each one backed up, hash-verified, journalled, and restored if the app touches a line that never had a link on it. `--link-rewrite {auto,off,require}` chooses the policy, and `FORGE_OBSIDIAN_CLI=off` turns the whole thing off. See `docs/obsidian-cli.md`. The note index gained an `aliases` field, so `vault-connections` rebuilds it once on the next run; embeddings are keyed separately by body hash and are not recomputed.
- Added a keyed provider tier and a daily budget ledger. Six search providers upgrade the registry when a free key is present — the Guardian and the New York Times for news, Wolfram|Alpha for computation, and Marginalia, Exa and Tavily as general indexes that are not scrapers of somebody else's engines — and each is skipped with a logged reason when no key is configured, so a machine nobody has set up behaves exactly as it did before. Four academic providers join the existing nine: OpenAlex, CORE, DBLP, and OpenCitations, which like Unpaywall takes the DOIs the search providers found rather than a query. Semantic Scholar and PubMed have declared an optional key since they were written and never read one; now they do. Most services publish a request rate, which spacing already handled, but OpenAlex and the NYT publish a daily allowance instead, so a ledger at `~/.pi-forge/cache/web-research/budget.json` skips an exhausted provider rather than retrying into a refusal. OpenAlex reports its own remaining balance on every response, and the ledger records what the service said rather than a local guess.
- Added `reference-resolve`, which asks one source which of its entries could be about a subject and answers with unranked candidates on stdout — no run directory, because a lookup is not a run — plus the `forge_reference_lookup` tool. Deciding which candidate is *about* a subject stays with the caller: a source's own relevance order is not that judgement.
- Added a routed search provider registry, so a question goes to a source that can answer it instead of always going through one metasearch scraper. Seventeen direct providers ship with no credentials at all — Wikipedia, Wiktionary and Wikidata; the Stanford Encyclopedia of Philosophy matched against its own published index, InPhO and the IEP; SuttaCentral, CBETA and BDRC; Open Library, Project Gutenberg, Internet Archive, the Library of Congress and HathiTrust; GDELT for news; Stack Exchange and Hacker News — and the query's identifiers and topic decide which are asked. An identifier is looked up rather than searched, because no document contains both the citation "MN 118" and the word it was asked alongside. SearXNG becomes the last provider tried rather than the only one, so a disabled or throttled instance now costs open-ended web results instead of the whole search. An optional `connectedServices.apiKeys` block upgrades providers that offer a free key; a provider without one is skipped with a logged reason, never an error.
- Added `forge/lib/http-fetch.mjs`, the shared outbound transport: retry with backoff honouring `Retry-After`, per-host request spacing, a circuit breaker, one SSRF guard in place of three divergent copies, and redaction of credential-bearing query parameters before any URL is archived. Before it, no HTTP call in the distribution retried — `withRetry` covered LLM calls only — and a timed-out fetch was recorded as a permanent failure because the message said "timed out" while the matcher looked for "timeout".

### Changed

- Changed `reviewer-2`'s comment callouts to a prefixed `r2-` namespace. A review comment is apparatus about an article, not content in a note, and the skill was borrowing the unprefixed built-ins: `structure` rendered as `[!abstract]`, putting a criticism of an article in the same cyan that now means "here is what this note is", and `strength` took the green that means "sourced and checkable". The six types are `r2-gap`, `r2-evidence`, `r2-logic`, `r2-theory`, `r2-structure`, `r2-strength`, styled as a left bar rather than a filled box so the article's own prose keeps the weight on the page, and red is available here because in a review a failure of logic is what red is for. `vault_format.py` treats `r2-` as a namespace and exempts it from the note registry. The strip grammar reads the old types as well as the new — it is built from `CATEGORIES` plus a `LEGACY_CALLOUTS` list — so a review copy rendered before the rename still round-trips exactly; dropping the legacy half would leave its comments unrecognised, and the strip is the only thing separating them from the author's prose.
- Changed `loom-notes.css` to live at `forge/lib/vault-format/loom-notes.css`. It sat under `vault-transcripts/references/` while three skills that do not own it referenced it by that path, and the vault's copy was kept in sync by hand. One home, and the agreement check now has a canonical file to read.
- Changed `vault-wiki` to resolve its canonical sources through the provider registry instead of its own copies. It carried Python resolvers for the SEP index, MediaWiki opensearch and WordPress search — the same three the registry implements — along with a private HTTP client, a private 7-day cache and a TLS context written to work around a Python that cannot find a CA bundle. All of it is gone; `canonical-sources.json` stays the editorial layer and each source now names a registry provider, or falls back to site-restricted search pinned to SearXNG because `site:` is SearXNG's syntax and means nothing to a direct API. The entry matching stayed in Python deliberately: it is calibrated against real failures — it keeps "The Theory of Two Truths in India" for the two truths doctrine while rejecting the SEP's entry on *truth* for the same note — so `reference-resolve` hands back every candidate unranked and vault-wiki still chooses. Verified against the live sources across a hundred (subject, source) pairs from a real vault: every one resolves to the same URL as before.
- Changed vault-wiki's two-second pre-emptive delay between searches to nothing. It was calibrated against a failure it could not see — a throttled instance answering HTTP 200 with an empty list — and now that such a response raises and backs off, pacing every request in advance buys little and costs latency on the majority that were never going to be throttled. The transport's per-host spacing replaces it. The workaround that deleted cached empty results is gone for the same reason, and with a comment saying so: an empty result now means the query genuinely matched nothing.
- Changed academic provider requests to go through the shared transport. They were the last hand-rolled `AbortController` and `setTimeout` in the distribution and never retried, so a 503 from Crossref simply failed the item. The archived request URL is now redacted before it is journalled, which matters as soon as a provider carries a key.

### Fixed

- Fixed the read-only phases of the vault workflow letting mutating `obsidian` commands through. `/plan` and `/verify` block mutating bash by pattern, and none of the Obsidian CLI's destructive subcommands match one: "rename" contains no `rm`, "move" contains no `mv`, and `eval` runs arbitrary JavaScript inside the app. So a model with bash could delete a note, rewrite links across the vault, or edit frontmatter during the two phases whose entire contract is that they change nothing. The gate now parses `obsidian` invocations — including through a wrapper, an absolute path, or after a pipe — and allows only the query subcommands by name, so a subcommand a future Obsidian release adds is blocked by default rather than waved through. Present whether or not any of the CLI integration is used.
- Fixed throttled SearXNG being indistinguishable from an empty result set. A rate-limited instance answers HTTP 200 with no results and lists the engines that refused in `unresponsive_engines`; both copies of the client read that as "this subject has no source", so a research run quietly returned a thinner answer rather than failing. The client now raises transiently on it and reaches the existing retry ladder, and the two copies became one in `forge/lib/searxng.mjs`.
- Fixed a rate limit being treated as a refusal. HTTP 429 counted toward the circuit breaker alongside 401/402/403, so GDELT — which answers 429 to anyone exceeding one request every five seconds and says so in the body — was permanently disabled mid-run for asking us to wait. A 429 now defers the host and retries; only a decision about us trips the breaker.

- Added an owner record, so an agent can use a person's name instead of calling them "the user" for an hour. The personal-context register gains an optional `## Owner` section holding a name and pronouns: `vault_profile` states it at the top of every prompt that already receives the card layer, and the `vault-context` extension reads that section alone — never the cards — so a session inside the vault is told who it is working with. Outside a vault a `forgeUser` entry in the agent's `settings.json` renders the same block into the installed profile on every install and update, which is what makes it survive one. The record is optional everywhere and gated like the cards are, so a stage held behind the fabrication check is still told no name at all, and an install that declares nobody behaves exactly as it did before.
- Added `reprocess` and `reconcile` modes to `vault-transcripts`. `reprocess` regenerates the summary, reflection, and cleaned text of every filed transcript note from its recording — reading it inline or through the link `split` left — while the note's name, its frontmatter, and the recording section survive byte for byte; therapy recordings are excluded by name, and a note the classifier reads as therapy while its name disagrees is held rather than rewritten. Its report shows every summary before and after. `reconcile` finds inbox exports whose recording is already in the vault by comparing the recording's text rather than the filename, and moves them to the recoverable quarantine so a re-export cannot grow a near-twin of a note the vault already had.
- Added `--only-sources` to `vault-organizer`'s vault mode, restricting a run to notes their own frontmatter calls sources. Turning on the sources tree is a migration for sources, but a whole-vault run files everything — including the hand-made folder trees people keep below a declared route, which drift checking deliberately ignores as legitimate structure. Paired with `--reuse-frontmatter` the migration runs with no model calls at all.
- Added `loom-notes.css`, a vault-wide Obsidian snippet styling the callouts the pipelines write — `[!summary]`, `[!abstract]`, `[!reflection]`, `[!connections]` — with theme-derived accents and lucide icons, in the same visual language as the dashboard snippet.
- Added an opt-in sources tree to the vault schema: declaring a **Sources root** section files every `type: source` note by its `source_kind` — `10 Sources/10.01 Book/Academic/Dissertation` — with the domain and subdomain labels as unnumbered subfolders that drift checking treats as detail, while the numbered kind folders are declared routes checked like any other. `project` never moves a source. Omitting the section leaves sources filing by domain exactly as before. `vault-organizer` gained `--reuse-frontmatter`, which files notes whose existing frontmatter already validates without a model call so a folder-only schema change does not re-derive a whole vault's classifications, and now pins a script-declared `type: source` and `source_kind` over the classifier's answer.
- Added a two-note transcript layout: processing writes the note made from the recording plus the recording under its own name as a `source_kind: transcript` source, linked from the note and back through `parent`, so a note reads at the length of what it says and the recording files with every other source. A new `split` mode moves the recording out of notes processed before this, deterministically and with every endpoint down, reconstructing byte-for-byte and backing up each note before rewriting it. Vaults whose schema cannot describe the second note keep the single combined note.
- Added a `vault-wiki` skill that installs the seven vault-owned wiki entry templates and expands thin entity notes into cited reference cards. Sources resolve through each canonical publisher's own API — Stanford Encyclopedia of Philosophy, Wikipedia, and per-topic equivalents — rather than through web search, so a citation names the work it came from. Only the sections a kind spec declares managed are rewritten: owner-authored `Notes`, frontmatter, and every unclaimed heading survive byte-for-byte, enforced by a post-merge comparison that fails the write rather than the check. Batch approval, per-id approval for anything the reviewer flagged, and a per-run revert.
- Added a `literature-library` skill that turns a citation list into a library: RIS/BibTeX parsing, bibliographic file naming, open-access acquisition with per-item deferral and `--retry-deferred`, and conversion of the acquired PDFs to Markdown under their bibliographic names, published through the hash-bound journal so a tampered file is caught by `validate`. Institutional access stays manual by design — the VPN it would need cannot be automated.
- Added a personal-context layer shared by `vault-capture`, `vault-transcripts`, `vault-organizer`, and `vault-connections`: a vault-owned register of cards compiled once and offered to each stage under `--profile` / `--no-profile`. Cards inform filing, drafting, and search wording; they are structurally forbidden from becoming note content, route-gated cards are refused wherever the destination is undecided, and an ambiguous or malformed register costs the layer rather than the run.
- Added reflection sections to generated memos alongside journals, with outside sources cited only when the material is already in hand — a link the person wrote, or a citation in a note the run imported. Nothing is fetched to support a reflection, and a connection citing anything else is dropped and reported rather than published.
- Added a schema marker for human-owned properties: a property the classifier is told nothing about, is stripped from the response if it answers anyway, and that the schema itself refuses unless it is declared optional. Lets a vault keep fields like `date` and `cover` that only a person can fill.

### Changed

- Changed `vault-capture` to render a note's reflection as collapsed callouts — `[!reflection]` per section, `[!connections]` for connections — matching what `vault-transcripts` writes, so generated material reads as generated in both kinds of note. Drafting still writes `##` headings and the deterministic checks still read them; the rewrap happens afterwards, on the way into the file, and takes only the trailing run of sections belonging to the note's kind, in that kind's order — a note that writes its own `## Next steps` mid-body keeps it. `render_callout` moves to `lib/vault_reflection.py`, beside the section vocabulary the two skills already share.
- Changed the `vault-transcripts` cleanup register from a light fidelity edit to spoken-to-written: filler and verbal scaffolding, false starts, repeated phrases, and circumlocutions whose meaning is unambiguous are removed, in the speaker's own words and voice, so a transcript reads as prose rather than as speech. Therapy recordings keep the older, stricter contract — nothing condensed, weighted hesitation preserved. The cleaned/source ratio floor moves from `0.5` to `0.4` and thirteen discourse adverbs join the stopword list, because a register that legitimately compresses would otherwise be held for review as though it had summarized. `PROMPT_VERSION` moves to `v5`, so run directories from before the change refuse to resume rather than mixing two registers.
- Changed the transcript note layout: everything the pipeline generates is now a callout and sits above the speaker's words — the summary open, each reflection and connections section collapsed — where reflections were previously bare `##` headings below the cleaned text and indistinguishable from headings the cleanup itself wrote. The generated apparatus is stripped out of the passage the fidelity reviewer sees, so a summary can no longer answer for a cleanup that dropped an utterance.
- Changed the seven `vault-wiki` templates to render the opening definition as an `[!abstract]` callout. Wrapping is idempotent, and notes that already exist keep their plain-prose leads until their next expansion.
